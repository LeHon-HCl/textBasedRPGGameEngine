# 反思报告（retros）

本目录存放**事件反思报告**：当某个事件暴露出**需要对文档体系做较大调整**时
（约束缺口、流程漏洞、检查盲区、设计对账失败等），在此留下完整的事后分析与改进结论。

## 为什么单独一层

- **与 `docs/reviews/` 区分**：`reviews/` 是**里程碑审查报告**（例行验收记录，格式固定）；
  本目录是**异常事件的深度复盘**（非例行、因事而写、结论可能推动流程/约束修订）。
- **与任务书/PR 描述区分**：任务书记录「做了什么」，PR 描述记录「这次改了什么」；
  反思报告回答「**为什么这类问题能发生、检查体系缺了什么、要不要改约束**」。
- **保留溯源**：约束文档（`docs/develop.md`）与设计文档的修订，常由某份反思报告触发。
  报告里保留完整证据链（实测输出、代码位置），便于日后复查「当时的判断是否仍成立」。

## 命名与格式

- 文件名：`<主题>-postmortem.md`（如 `content-integrity-postmortem.md`）。
- **文首必须**包含：触发场景、审查对象、结论摘要、状态（待审查 / 已采纳 / 部分采纳）。
- 正文建议按「事实清单（经执行验证）→ 根因分析 → 责任归属 → 改进建议」组织；
  **事实必须可复现**（附命令、代码位置、实测输出），不写推测性结论。
- 报告**只做归因与建议**；约束/设计的实际修订另行走文档变更流程（约束 2：须人类审查点头）。

## 与其他文档的关系

| 文档 | 关系 |
|---|---|
| `docs/develop.md` 约束 3 | 本目录的产生与引用规则（反思报告的触发条件与用途） |
| `docs/develop.md` 约束 2 | 由反思报告引发的文档修订，同样须经人类审查点头 |
| `docs/reviews/` | 里程碑例行审查报告（不同性质，勿混放） |
| `docs/archive/` | 失效文档归档（本目录文档是**生效中的**复盘结论，不归档） |
