# 分工文档模板（多人协作标准结构）

> 来源：2026-09-21 采纳自 M2 阶段二复盘报告（`docs/retros/m2-stage2-collaboration-postmortem.md`）
> 建议 1/3/4。阶段三起，凡多人协作的阶段一律复制本结构；单人阶段在计划文档里
> 声明「全单线」即可，不必套用。

## 0. 防重复劳动与防能力重叠（硬规则）

1. **先认领后动工**：认领 = 从最新 main 切分支 `feat/<模块>-<工作包>` + **立即开
   draft PR 占位**（标题 `[<模块>-<工作包>] …`），描述写明「认领 X（见本分工文档）」
   与认领人。**draft PR 创建时间 = 认领时间，先到先得**。
2. **开工前检索义务**（建议 1，防「跨工作包能力重叠」）：
   认领前必须检索两处——
   - main 上的既有能力：`git log --oneline main -- <候选目录>` + 实际翻目录内容；
   - 开放 PR 的标题与描述中的同职能关键词（`gh pr list --state open`）。

   发现疑似重叠（同职能模块/同语义字段/同职责服务）→ **在对应 PR 或 issue 提出，
   先对齐后动工**。阶段二的 driver 撞车的成因正是这条缺失：认领规则只防「同一工作包
   被两人认领」，防不了「不同工作包各自实现同一能力」。
3. **文件所有权表**：逐文件（或目录）到人；改动对方名下文件必须走对方 review。
4. **公共契约冻结**（建议 4，阶段二验证有效）：核心类型文件（`types.ts` 类冻结面）
   在第一个工作包内先行冻结；此后变更**只增不改**（additive），破坏性变更必须
   对方 review 同意 + PR 描述说明迁移方式。
5. **契约变更显式声明**：跨所有权文件或公共契约的改动，须在 PR 描述与自审清单
   「跨所有权/契约变更」项注明（develop.md PR 自审清单）；惯例变检查项（建议 3）。
6. **串行包的前置遵守**：共同前置（如接口冻结）未合入前，后续包只能认领不能写代码；
   提前认领占位允许。

## 3. 协作与验收约定

- **review 义务**：每包 PR 由**另一位开发者** review；公共契约变更 review 是硬性前置。
- **完成定义**（每包）：对应子任务勾选 + 各自测试全绿 + 四门禁 + validate-docs 绿
  + 自审清单填全。
- **里程碑完成定义**：模块子任务全勾 + 模块级验收用例通过 + 收尾 docs
  （任务文件落地记录 / progress.md / architecture.md）。
- **收尾**：docs 收尾 commit + 里程碑反思报告（约束 4）+ 人工验收（约束 10）。

## 4. 合并规程（引用）

合并按 develop.md 约束 9「PR 合并规程」执行：显式 PR 号 / CI 绿后合 / 合后同步 main。
