### 关键设计点（**Q0 已核实**，2026-09-23）

1. **回滚与 session 重建 —— 需人类决策的一处口径**：
   - 现状（M1 实现）：`game-host.rollbackTo` 回滚状态后**重开会话到 `entryScene`**
     （manifest 入口场景）——即**回滚会丢失叙事位置**（无论回滚几步，都回到开局场景）；
   - 引擎侧能力：`SceneRunner` 已有**环形历史缓冲**（500 段，`NARRATIVE_HISTORY_CAPACITY`）
     与 `NarrativeHistoryEntry`（含 seq / 场景 / 段落文本）——具备「按历史条目
     重新进入指定场景」的数据基础；
   - **M2 验收第 4 条「回滚 5 步状态一致」的口径需二选一**：
     - **口径甲（状态一致，叙事位置不保证）**：验收只断言状态树一致
       （attrs/flags/wallet/任务/时间），叙事位置回到 entryScene 属已知行为。
       实现成本：零（现有能力即满足），B2 只写验收用例；
     - **口径乙（状态 + 叙事位置都一致）**：回滚后重开会话到**该次 checkpoint 记录
       的场景**（需要 checkpoint 元数据扩展：记录 sceneId + 段落序号），
       并支持「恢复到第 N 段」。实现成本：引擎侧 checkpoint 元数据 additive 扩展
       （`CheckpointMeta` 加 `sceneId?` + host 侧重建逻辑）+ 历史回看与回滚的
       联动测试；约半天到一天。
   - **裁定（2026-09-23 人类审查）：采用口径甲**——M2 验收第 4 条只断言**状态树
     一致**（attrs/flags/wallet/quests/time/npcs 等逐字段），叙事位置按设计 §6.3
     原文回 `entryScene`（「回滚只还原状态，叙事位置须重开会话」）。
     口径乙（叙事位置精确还原，需 `CheckpointMeta` 扩展 + `SceneRunner.restoreTo`）
     **登记为 M4 打磨项**（与 25C 回想/图鉴一并处理更划算；届时需先按约束 2 改设计）。
   - 补强措施（低成本）：B1 的历史回看面板提供回退前后的文本可追溯性，
     与口径甲组合后玩家体验接近「可回溯」，无需引擎改动。
2. **战斗面板与叙事的关系**（OQ-04）：设计裁定「嵌入叙事区的独立面板」——
   宿主消费 `battle_start` 事件后，在叙事区上方/内嵌渲染战斗面板，关闭后
   `pollOutcome().jumps` 注回叙事（契约已在 #33 定死）。
3. **调试面板的开关 —— 需 additive 扩展**：manifest schema **无** `debug` 字段
   （Q0 核实）；落地时需加 `debug: boolean`（可选，additive）+ 快照基线级联再生。
   语义：`debug: true` 时玩家端启用调试面板（DoL 式开发者模式，需求 FR-DEBG-01）。
4. **历史回看的数据面已完全就绪**：`SceneRunner` 环形历史缓冲（500 段）+
   `NarrativeHistoryEntry`（seq/场景/文本）+ **只读读取 API `history()`** 均已由
   08 号交付——B1 纯 UI 工作，引擎侧**零改动**。

## 2. B 线实施发现（2026-09-23）：回滚栈深边界 —— 需人类知情的验收口径澄清

**发现**：`PERF_GUARD.checkpointStackDepth = 5`（引擎性能护栏常量）——检查点栈深
上限为 5，超深自动丢弃最旧快照。因此：

- **「回滚 5 步」的精确含义**：连续 6 次选择后，栈内保留「第 2..6 次选择前」的
  5 个快照，恰好可回退 5 步（回到第 2 次选择之前）；
- **若只做 5 次选择**，第 1 个快照已被挤出，实际只能回退 4 步——「回滚 5 步」
  在恰好 5 次选择时**不可达**；
- B2 验收用例已按此口径实现（6 次选择 → 回滚 5 步 → 状态逐字段一致 + 重放复现）。

**影响与选项**：

| 选项 | 说明 | 成本 |
|---|---|---|
| A（现状，已按此验收） | 栈深 5 是性能护栏；「回滚 5 步」= 6 次选择后回退 5 步 | 零 |
| B：提高栈深 | 调 `PERF_GUARD.checkpointStackDepth`（如 10）——但「回滚 N 步」仍受同一
边界约束，只是 N 的上限变大；快照体积 ×N（每快照为全量状态克隆，>5MB 有告警） | 改一个常量 + 回归测试（快照体积/性能护栏测试可能需同步） |

**裁定（2026-09-24 人类审查）：维持 A** —— 栈深 5 为刻意的性能护栏；「回滚 5 步」
的验收口径即「6 次选择后回退 5 步」（B2 用例已按此实现）。若将来玩家侧需要更长
回退深度，按选项 B 调整（改常量 + 快照体积回归）。
