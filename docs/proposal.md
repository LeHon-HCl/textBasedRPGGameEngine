## 1. 项目概述

### 1.1 背景

文字冒险 / 文字 RPG 是一类以文本叙事为核心、辅以数值与系统深度的游戏形态。代表性的成品与工具各有局限：

- **Twine / SugarCube**：可视化创作友好，但只有「叙事 + 变量」这一层。要做 DoL（Degrees of Lewdity）这种量级的系统（时间、日程、服装、好感、事件池），作者必须手工堆叠大量胶水代码，且多语言、版本迁移、内容过滤等工程问题全部自行解决。
- **Ren'Py / 橙光**：演出与工具链成熟，但分别绑定 Python 桌面生态与中心化商业平台，前者 Web 分发弱，后者无独立分发能力且不支持原生多语言。
- **CoC / TiTS / Lilith's Throne 等成品**：系统深度足够，但引擎与内容耦合，无法复用于新作品。

本项目的目标：**用 React + TypeScript 自研一个纯前端的文字 RPG 引擎 + 可视化编辑器**，把上述「系统深度、创作效率、工程化（i18n / 存档兼容 / 内容分级）」合并为一套开箱即用的能力，让作者只需关心剧情与设计。

### 1.2 产品定位

> 一个纯前端的文字冒险游戏引擎与配套可视化编辑器：数据驱动、高自由度多区域探索、事件/任务驱动、CoC 式判定与回合制战斗、双循环进度（同存档周目 + 跨存档成就增益）、原生多语言、长线版本演进（更新不废档）。

产品由三部分组成：

1. **engine（运行时核心）**：纯 TypeScript 库，无 DOM 依赖。负责加载游戏包、维护游戏状态、执行表达式与效果指令、驱动全部游戏系统。
2. **runtime-ui（玩家界面）**：基于 React 的通用游玩界面，渲染文本/媒体/面板，可被游戏级主题定制。
3. **editor（可视化编辑器）**：面向作者的创作工具，产出标准「游戏包」，并提供预览调试、校验、翻译管理、发布导出。

### 1.3 目标用户

| 用户 | 描述 | 核心诉求 |
|---|---|---|
| 玩家 | 在浏览器或桌面端游玩导出游戏的最终用户 | 流畅阅读、自由探索、存档安全、多语言、内容过滤 |
| 作者 | 独立开发者 / 文字游戏爱好者，用编辑器创作游戏 | 低门槛写剧情、系统开箱即用、可调试、可发布、可更新 |
| 译者 | 为游戏包提供其他语言文本的贡献者 | 只碰文本文件、不接触逻辑、缺失翻译可检测 |
| Mod 作者 | 为已发布游戏制作数据覆盖包（P2） | 不改原包即可叠加内容 |

### 1.4 参考对象

DoL（Degrees of Lewdity）、CoC / CoC2 / TiTS、Lilith's Throne、Twine / SugarCube、Choice of Games（ChoiceScript）、ink、Ren'Py、橙光 / 易次元。逐项对比见 §2。

### 1.5 非目标（明确不做）

- **任何后端**：无账号、无云存档、无在线平台、无数据上报。分发形态是纯静态文件。
- **多人联机 / 异步交互**。
- **默认集成 AI**：AI 辅助创作仅作 P3 占位，默认关闭且需用户自带 API Key。
- **重视觉演出**：不做 Live2D、口型、骨骼动画；媒体支持限于静态图片与音频。
- **内容本身**：引擎不附带任何剧情/素材，仅提供机制；内容责任归具体游戏的发布者（见 §8 合规说明）。

### 1.6 优先级与里程碑标记

| 级别 | 含义 | 对应里程碑 |
|---|---|---|
| P0 | 核心可用，缺失则产品不成立 | M0–M1 |
| P1 | 正式版必备，构成完整产品体验 | M2–M4 |
| P2 | 增强功能，写入需求、后期交付 | M5 及以后 |
| P3 | 远期展望，仅保留架构占位 | 不排期 |

### 2.3 差距分析与补充结论

对比结论（对照本文档 v1–v6 计划稿）：

1. **已覆盖**：叙事/变量/探索/事件/任务/四大核心系统/战斗判定/成就/周目/迁移/i18n 等主体能力，与 DoL 级系统深度对齐。
2. **v7 补充（P1）**：媒体资源系统、身体与变身、经济与商店、阵营声望、阅读 QoL（已读跳过/自动播放/回滚）、回想图鉴与结局收集、统计页面、调试与作弊面板。这些是 Ren'Py / DoL / CoC 长期验证过的「留存型」功能。
3. **v7 补充（P2）**：物品合成、同伴/队伍、程序化内容生成、Mod 数据覆盖包、游戏级 UI 主题、百科 Codex（见 §5.24）。
4. **远期（P3）**：AI 辅助创作（编辑器内 LLM 草拟文本，默认关闭）。
5. **引擎级差异化优势**：原生 i18n（所有竞品均缺）、版本迁移不废档（Twine 生态最大痛点之一）、内容分级过滤（引擎中立机制）。

## 3. 用户角色与核心场景

### 3.1 玩家旅程

1. 打开游戏（网页链接或 Electron 应用）→ 主菜单（继续 / 新游戏 / 读档 / 成就 / 设置 / 关于）。
2. 首次启动：内容设置向导（选择界面语言、阅读内容标签开关，见 §5.21）。
3. 新游戏：可选角色创建（姓名等，由游戏定义）→ 若 Profile 中有成就点数，进入开局增益（Perk）选择界面 → 进入开场。
4. 游玩主循环：阅读文本 → 在世界地图/当前地点选择行动（移动/探索/交互/推进时间）→ 触发事件或场景 → 选项分支 / 判定 / 战斗 → 数值、物品、好感、任务状态变化 → 循环。
5. 阶段终点：达成结局 → 周目转场（继承规则生效，进入下一周目，周目专属内容解锁）；或成就解锁（Toast 通知，点数入 Profile，供**新开档**消费）。
6. 随时：多槽位存档 / 自动存档 / 导出存档备份；跳过已读、自动播放、回滚上一选择；查看任务日志、统计页、回想图鉴。

### 3.2 作者旅程

1. 打开编辑器 → 新建游戏项目（选择模板或空白）。
2. 定义世界骨架：区域 → 地点 → 场景拓扑（节点画布）；配置时段制、属性表、初始状态。
3. 填充系统数据：NPC（日程/好感阈值）、物品与服装、身体部位模板、商店、事件池、任务线、成就与开局增益、结局与周目规则。
4. 编写叙事：场景富文本 + 叙事宏 + 选项（条件/效果/跳转）；写作产生的文本自动落入 `locales/` 文本键（见 §5.1）。
5. 预览调试：一键试玩、变量监视、跳转任意场景、时间快进、周目模拟。
6. 校验：引用完整性（悬空跳转/文本键/物品引用）、表达式错误、翻译缺失。
7. 发布：版本号 + 变更记录 → 生成迁移脚手架（如数据结构有变）→ 导出静态文件包 → 托管分发。
8. 更新：修改内容后再次导出；玩家旧存档经迁移链自动升级（§5.19），不废档。

### 3.3 译者旅程

1. 获得游戏包（或编辑器导出的翻译工作包：主语言文本 + 空白目标语言模板）。
2. 在 `locales/<lang>/` 下按命名空间翻译 YAML 文本文件；全程不接触 `data/` 逻辑。
3. 使用编辑器「翻译管理」查看缺失/过期键统计；导出导入 CSV/XLIFF 与外部翻译流程协作。
4. 运行时缺失译文自动回退主语言并告警（§5.1），翻译可渐进完成不阻塞发布。

### 3.4 双循环进度模型

引擎提供两条独立、可组合的长线进度循环，避免混淆：

```
循环 A：同存档「周目」（FR-LOOP，作者配置继承/重置清单）
   玩家档 ─游玩→ 结局 ─继承部分状态→ 下一周目（同档继续，loop+1）
                                    └→ 周目数解锁新事件/区域/对话变体

循环 B：跨存档「成就点数 → 新档增益」（FR-ACHV，存于 Profile）
   任意存档 ─解锁成就→ 点数入 Profile（不随读档回滚/删档丢失）
   Profile 点数 ─新开游戏时→ 兑换开局 Perk（属性/物品/内容解锁）
```

### 3.5 Mod 作者旅程（P2）

获得游戏包后制作「数据覆盖包」（overlay）：只含差异数据的 `data/`、`locales/`、`assets/` 片段与 mod manifest；玩家在设置中启用，按声明顺序叠加，不修改原包文件。见 §5.24。

## 4. 总体架构与技术选型

### 4.1 分包结构（pnpm monorepo）

```
textBasedRPGGameEngine/
├─ packages/
│  ├─ engine/        # 运行时核心：状态机、系统、表达式、效果指令、迁移、存档服务（纯 TS，无 DOM）
│  ├─ runtime-ui/    # 玩家界面：React 组件库 + 默认布局 + 主题机制
│  ├─ editor/        # 可视化编辑器（React 应用）
│  ├─ shared/        # 共享类型（游戏包 schema）、表达式语法定义、校验规则、工具函数
│  └─ exporter/      # 静态包导出 / Electron 打包器（CLI + 编辑器内调用）
├─ apps/
│  ├─ player-demo/   # 引擎 + runtime-ui 的最小宿主页面（开发与测试用）
│  └─ editor-app/    # editor 的部署外壳
└─ examples/
   └─ demo-game/     # 官方示例游戏包（3 区域、事件、任务、战斗、成就、双语）
```

分层原则：

- `engine` 不依赖 DOM/React，可独立单测，也能被编辑器嵌入用于预览。
- `runtime-ui` 只消费 engine 的公开 API 与状态订阅，不含游戏逻辑。
- 所有「游戏内容」存在于数据包中，四个包本身不含任何剧情。

### 4.2 运行时数据流

```
编辑器产出游戏包（data + locales + assets + manifest）
        │  加载与校验（Zod/JSON Schema）
        ▼
engine：GameRuntime 实例
  ├─ GameState（单一状态树，含版本、周目、玩家、世界、NPC、任务、图鉴…）
  ├─ 表达式求值器（AST 解释，无 eval）
  ├─ 效果指令执行器（set/give/quest/check/battle/…原子操作，含 undo 快照）
  ├─ 系统调度（时间推进→事件池评估→状态 tick→NPC 移动）
  └─ 持久化（存档槽位 / Profile，IndexedDB）
        │  状态订阅（细粒度 selector）
        ▼
runtime-ui：文本渲染（文本键→当前语言→插值→白名单富文本）、面板、媒体、交互
```

### 4.3 游戏包目录结构规范

```
my-game/
├─ manifest.json           # 游戏名、入口场景、主语言、支持语言列表、内容标签声明、
│                          #   gameVersion / schemaVersion / 最低引擎版本、Perk/成就开关
├─ data/                   # 全部逻辑数据（不含任何面向玩家的文本）
│  ├─ attrs.yaml           # 属性/技能/状态效果定义
│  ├─ areas/               # 区域→地点→场景拓扑（含解锁条件）
│  ├─ scenes/              # 场景（段落+宏+选项，文本走键引用）
│  ├─ events.yaml          # 事件池（触发条件/概率/冷却/标签）
│  ├─ quests/              # 任务线（阶段/目标/奖励/依赖）
│  ├─ npcs/                # NPC（日程/好感阈值/立绘引用）
│  ├─ factions.yaml        # 阵营声望
│  ├─ items/               # 物品/装备/服装（部位×层）
│  ├─ body.yaml            # 身体部位模板与取值集
│  ├─ shops.yaml           # 商店与定价表达式
│  ├─ achievements.yaml    # 成就（条件/点数/隐藏）
│  ├─ perks.yaml           # 开局增益
│  ├─ endings.yaml         # 结局（含周目入口标记）
│  ├─ loops.yaml           # 周目继承/重置清单
│  ├─ content-tags.yaml    # 内容标签与默认过滤策略
│  └─ migrations/          # 存档迁移脚本链（v1→v2.ts …）
├─ scripts/                # 作者脚本轨（FR-SCR）：TS 自定义指令/条件函数/检定规则/系统钩子，导出时编译进包
├─ locales/                # 全部面向玩家的文本（按语言分包）
│  ├─ zh-CN/  { scenes/ npcs/ items/ quests/ ui/ … }
│  └─ en-US/  …
├─ assets/                 # 媒体（img/ audio/ themes/）
├─ stats-page.yaml         # 作者自定义统计页布局
└─ changelog.md
```

> 目录为规范草案，实现期可在不破坏「data / locales / assets 三分离」原则下微调。

### 4.4 核心状态模型（GameState 草案）

```
GameState
├─ versions        # engineVersion / gameVersion / schemaVersion（迁移依据）
├─ loop            # 当前周目数
├─ player          # attrs / skills / statuses / body / equip / outfit / bag / wallet
├─ world           # time(day,weekday,slot) / unlockedAreas / flags / counters
├─ npcs            # {id: favor / stage / flags / met}
├─ factions        # {id: reputation}
├─ quests          # {id: state / stage / objectivesProgress}
├─ seen            # 已读场景键集合 / 回想解锁 / 结局解锁 / 百科解锁
├─ readStats       # 用时 / 天数 / 事件计数 / 判定计数等
├─ settings        # 语言 / 文本速度 / 标签过滤 / 主题
└─ checkpoints     # 回滚快照栈（选择粒度）
# Profile（独立于 GameState 持久化）：achievements / points / purchasedPerks
```

### 4.5 表达式语言（受限 DSL）

- **形态**：中缀表达式，支持算术（`+ - * / %`）、比较（`== != < <= > >=`）、逻辑（`&& || !`）、三元、函数调用。
- **变量域（白名单）**：`attr.*`、`skill.*`、`flag.*`、`item.<id>.count`、`outfit.<slot>`、`body.<part>`、`npc.<id>.favor`、`faction.<id>`、`time.day / time.weekday / time.slot`、`loop`、`meta.points`、`fn.has() / fn.worn() / fn.rand(a,b)` 等。
- **实现约束**：解析为 AST 后由引擎解释执行，**禁止 eval / new Function**；加载期静态校验（未知变量、类型错误在编辑器与控制台同时报出）。
- **语法版本化**：表达式语法纳入 schemaVersion 管理，后续只增不改，避免旧包失效。
- **作者扩展**：内置函数白名单可经「作者脚本轨」注册扩展（FR-SCR）；扩展函数随游戏包版本管理，静态校验对扩展函数同样生效。

### 4.6 技术选型

| 领域 | 选型 | 理由 | 备选 |
|---|---|---|---|
| UI 框架 | React 18 + TypeScript 5 | 既定决策；类型系统承载 schema | Vue 3 |
| 构建 | Vite | 开发体验、库模式多包构建 | tsup（库） |
| Monorepo | pnpm workspace（+ Turborepo 可选） | 轻量、脚本编排 | Nx |

| 数据格式 | YAML（创作）+ JSON（运行时编译产物） | YAML 利于人写；导出时编译为 JSON 提升加载性能 | JSON5 |

| 虚拟滚动 | react-window | 长历史日志/任务列表性能 | — |

### 4.7 全局设计约束

1. **纯前端**：任何功能不得隐含网络依赖（P3 AI 为用户显式开启的例外）。
2. **数据驱动、引擎中立**：引擎不理解题材语义（如「服装遮挡」「身体部位」只是数据字段，语义由具体游戏的表达式与文本决定）。
3. **ID 稳定性**：一切跨存档引用的对象（场景/物品/NPC/任务/成就/文本键）以不可变字符串 ID 为主键；编辑器对删除/重命名给出影响警告（§5.19、§5.23）。
4. **可回滚**：GameState 更新必须可快照（immer），支撑回滚、调试与迁移前备份。
5. **失败要响**：数据错误、悬空引用、迁移失败必须显式报错并给出诊断信息，禁止静默吞错。

## 5. 功能性需求

编号规则：`FR-<模块>-<序号>`，标注优先级（P0/P1/P2，定义见 §1.6）。每个模块先给定位说明与数据形态示例（示例为示意草案，以实现期 schema 为准），再列需求条目。验收以「里程碑用例」（§7）为准。

### 5.1 文本资源与本地化（FR-L10N）

**定位**：全文渲染的唯一入口。游戏逻辑数据中不出现任何面向玩家的文本，一律以文本键引用 `locales/` 下的语言包（决策 D4）。这是引擎差异化能力，必须在 M0 即落地。

数据形态示例：

```yaml
# locales/zh-CN/scenes/tavern.yaml
tavern:
  greet: "酒馆老板朝你点头：「又是你啊，{player.name}。」"
  intro_first: "你第一次推开这扇门，烟味扑面而来。"
  intro_again: "熟悉的烟味。你已经来过 {stats.tavern_visits} 次了。"
# data/scenes/tavern.yaml 中仅存引用：
# segments: [ {text: "tavern.greet"}, {text: "tavern.intro", alt: {first: "tavern.intro_first", again: "tavern.intro_again"}} ]
```

- **FR-L10N-01【P0】文本键体系**：全局唯一文本键，按命名空间（scenes/npcs/items/quests/ui/…）组织；引擎提供按键取文与按命名空间批量加载。
- **FR-L10N-02【P0】语言包结构**：`locales/<lang>/**.yaml` 与键命名空间目录镜像；manifest 声明主语言与支持语言列表。
- **FR-L10N-03【P0】变量插值**：文本支持 `{player.name}`、`{npc.molly.favor}` 等变量插值与简单格式化（数值精度、正负号）；插值失败时显示原始占位并在控制台告警。
- **FR-L10N-04【P1】复数与语法变体**：支持 `one/other` 复数键与按表达式选择文本变体（`select: {gender: {male: …, female: …}}`），满足多语言语法差异。
- **FR-L10N-05【P0】运行时语言切换**：设置面板切换语言即时生效，无需重载存档。
- **FR-L10N-06【P0】缺失回退**：目标语言缺失键时回退主语言并以高亮/日志标记，翻译可渐进完成不阻塞游玩。
- **FR-L10N-07【P1】完成度统计与校验**：引擎/编辑器报告每语言缺失键、未使用键、插值占位符不一致；导出发布时作为校验项（§5.23）。
- **FR-L10N-08【P1】翻译工作包**：编辑器可导出/导入 CSV、XLIFF 格式翻译工作包（主语言 ↔ 目标语言对照）。
- **FR-L10N-09【P0】引擎 UI 自身多语言**：runtime-ui 与 editor 界面文案走同一套机制，首发 zh-CN、en-US。

### 5.2 叙事核心（FR-NARR）

**定位**：场景、选项、叙事宏构成内容的基本单元，是其余系统（事件/任务/战斗/结局）的展示载体。

数据形态示例：

```yaml
# data/scenes/tavern_bar_fight.yaml
id: tavern_bar_fight
entry: { require: "attr.courage >= 3 || npc.raven.favor > 20" }
segments:
  - text: "tavern.fight.desc"          # 文本键
  - macro: { if: "body.species == 'beast'", then_text: "tavern.fight.beast", else_text: "tavern.fight.human" }
choices:
  - id: fight
    text: "tavern.fight.opt_fight"
    show_if: "attr.courage >= 5"
    effects: [ {check: {type: coc, skill: "skill.brawl", difficulty: hard, on_success: "scene_win", on_fail: "scene_lose"}} ]
  - id: flee
    text: "tavern.fight.opt_flee"
    effects: [ {add_flag: "fled_from_fight"}, {goto: "tavern_door"} ]
```

- **FR-NARR-01【P0】场景模型**：场景 = 元信息 + 进入条件 + 段落序列 + 选项列表 + 场景级媒体绑定（图/BGM，见 §5.14）与内容标签。
- **FR-NARR-02【P0】选项与条件分支**：选项支持显示条件 `show_if`、可用但置灰条件、一次性选项（选过隐藏）、效果序列与跳转（`goto` 场景 / 返回上层 / 结束事件）。
- **FR-NARR-03【P0】效果指令集**：原子效果至少覆盖：`set/add`（变量、属性）、`give/take`（物品）、`equip/wear/remove`（装备服装）、`set_body`（部位）、`favor`（好感）、`reputation`（声望）、`money`（货币）、`flag`、`goto`、`advance_time`、`quest_*`（接取/推进/完成/失败）、`check`（判定）、`battle`（战斗）、`unlock_*`（回想/结局/百科/成就）、`media`（播图/音）、`notify`（提示）。指令可声明条件与顺序，执行失败即报错定位。内置指令之外，作者可经脚本轨注册自定义指令（§5.26）。
- **FR-NARR-04【P0】叙事宏**：段落内支持条件文本（if/else）、首次与再次文本区分（first/again）、随机选段（权重）、延迟插值片段。
- **FR-NARR-05【P0】富文本渲染**：白名单标签（粗体/斜体/着重/颜色/分隔/换行等）经 sanitizer 渲染；白名单外标签一律转义显示（安全要求见 §6.5）。
- **FR-NARR-06【P1】场景模板与复用**：场景可声明参数化模板（如通用战斗遭遇/商店对话框架），减少重复数据。
- **FR-NARR-07【P1】文本量统计**：编辑器显示场景/选项的字数与阅读时长估算，辅助创作管理。

### 5.3 探索与事件（FR-XPLR）

**定位**：高自由度结构（决策 D2）。「区域 → 地点 → 场景」组成世界拓扑，玩家自主移动与行动；事件按条件/概率/主动探索三类方式触发。

数据形态示例：

```yaml
# data/areas/riverside.yaml
id: riverside
name_key: area.riverside
locations:
  dock:  { name_key: "area.riverside.dock", unlock_if: "flag.ferry_open", map_pos: [120, 80] }
  market: { name_key: "area.riverside.market", move_cost_slots: 1 }
# data/events.yaml（节选）
- id: ev_pickpocket
  where: { area: riverside, location: market }
  when: { slots: [evening, night], weekdays: [fri, sat] }
  trigger: { type: random, weight: 10, require: "item.gold.count >= 20", cooldown_days: 3, once_per_loop: false }
  tags: [crime, minor_violence]        # 内容分级标签（§5.21）
  scene: ev_pickpocket_scene
```

- **FR-XPLR-01【P0】三级拓扑**：区域（Area）/地点（Location）/场景（Scene）层级建模；区域与地点有名称键、地图坐标（用于地图 UI）与解锁条件。
- **FR-XPLR-02【P0】世界地图与导航**：地图 UI 展示已解锁区域/地点；移动消耗时段可配置（`move_cost_slots`）；锁定的地点显示为未知/可达条件提示（文案由游戏配置）。
- **FR-XPLR-03【P0】事件池**：事件绑定到「区域/地点 × 时段/星期 × 条件」；每时段推进与进入地点时评估事件池。
- **FR-XPLR-04【P0】三类触发方式**：① 条件型（满足即触发，如剧情关键节点）；② 概率型（权重随机，支持冷却 `cooldown_days/slots`、每周目一次、每存档一次）；③ 探索发现型（玩家在地点执行「探索」动作时按条件+权重呈现交互点）。
- **FR-XPLR-05【P0】优先级与互斥**：事件支持优先级排序与互斥组（同组同时至多触发一个），保证叙事节奏可控。
- **FR-XPLR-06【P0】时段联动**：事件与时间系统联动（时段、星期、季节字段可选）；「错过窗口」的事件按配置丢弃或排队。
- **FR-XPLR-07【P1】快速旅行**：已到达过的地点间快速移动（条件与代价由游戏配置）。
- **FR-XPLR-08【P1】探索动作配置**：地点可配置自定义行动（垂钓/搜索/休息…），行动 = 效果 + 事件入口 + 时段消耗。

### 5.4 任务系统（FR-QUEST）

**定位**：可选接取、多阶段推进的进度载体；任务日志是玩家长期目标感的来源。

数据形态示例：

```yaml
# data/quests/missing_cat.yaml
id: missing_cat
giver: npc.old_lady
accept_if: "time.day >= 3 && faction.town >= 0"
stages:
  - id: search_dock
    objective_key: "quest.missing_cat.obj_search"      # 目标文本键
    complete_when: "flag.cat_found"
  - id: return_cat
    objective_key: "quest.missing_cat.obj_return"
    complete_when: "flag.cat_returned"
rewards: [ {money: {gold: 50}}, {favor: {npc: old_lady, amount: 15}} ]
fail_when: "time.day > 10 && !flag.cat_found"
conflicts: [rat_problem]        # 互斥任务
```

- **FR-QUEST-01【P0】任务定义**：接取条件、多阶段目标（`complete_when` 表达式驱动状态机推进）、奖励效果、失败条件、可选时间限制。
- **FR-QUEST-02【P0】任务状态机**：未发现 / 可接取 / 进行中（当前阶段）/ 待提交 / 完成 / 失败；状态变化可触发效果与事件。
- **FR-QUEST-03【P0】任务日志 UI**：按状态分组展示、目标文本、追踪置顶（同时追踪数可配置）、 giver/地点指引（文本键描述）。
- **FR-QUEST-04【P0】依赖与互斥**：任务可声明前置任务与互斥任务，支持分支任务线。
- **FR-QUEST-05【P1】任务变量展示**：目标文本支持插值任务进度（如「木材 3/5」）。

### 5.5 数值系统（FR-STAT）

**定位**：角色强度与状态的数字化基础，为表达式、判定、事件条件提供变量域。

- **FR-STAT-01【P0】属性定义**：数值型属性（min/max/初始值/显示名键/隐藏开关）与等级型属性（离散等级表）；属性可标记「可被玩家查看」或「仅内部计算」。
- **FR-STAT-02【P0】技能与成长**：技能 = 属性的一种，附加经验曲线（使用/事件获得经验，阈值升级）或点数购买升级，策略由游戏配置。
- **FR-STAT-03【P0】状态效果（Buff/Debuff）**：时长（时段制或回合制）、触发时机（获得/每时段/每回合/到期）、叠加策略（刷新/叠层/取强）、来源标记；数值修正以「基础值 + 修正项」计算，面板显示修正明细。
- **FR-STAT-04【P0】属性变化通知**：数值变化在 UI 侧栏以增量高亮（+2 / -5）与可选 Toast 呈现。
- **FR-STAT-05【P1】派生属性**：属性可声明由表达式派生（如 `attr.max_hp = 10 + attr.con * 3`），派生链循环依赖在加载期报错。
- **FR-STAT-06【P1】成长门槛通知**：升级、新状态获得时按配置推送提示文本。

### 5.6 时间与日程（FR-TIME）

**定位**：DoL 式时间骨架。时段推进是事件评估、NPC 移动、状态 tick 的心跳。

- **FR-TIME-01【P0】可配置时段制**：时段列表与顺序由游戏定义（如 早/午/晚/夜 或更细粒度）；支持 星期（7 天可改名）、日 → 周 → 月 → 年递进（月/年可选启用）。
- **FR-TIME-02【P0】时间推进**：行为消耗时段（移动/行动/事件可声明消耗）；跨天时触发「日结算钩子」（周目外循环：房租/惩罚/总结等由游戏定义）。
- **FR-TIME-03【P0】时段推进钩子**：每时段推进依序执行：状态效果 tick → NPC 日程移动 → 事件池评估（§5.3）→ 到期任务判定。执行顺序固定并写入文档（作者可预期）。
- **FR-TIME-04【P0】NPC 日程**：NPC 按时段 × 星期配置所在地点，附加条件（`show_if` 表达式，支持周目/flag）；玩家在同一地点才能交互。
- **FR-TIME-05【P0】日历 UI**：显示第几周几星期几时段；可查看今日剩余行动提示（游戏可配置）。
- **FR-TIME-06【P1】时间感知文本**：文本宏可按时段/天气（若游戏定义）选择变体描写。

### 5.7 物品与服装（FR-ITEM）

**定位**：物品是经济、任务、判定的通用媒介；多层服装是 DoL 特色系统。

- **FR-ITEM-01【P0】物品定义**：类型（普通/消耗品/装备/服装/关键道具）、堆叠规则、使用效果与使用条件、描述文本键、图标引用。
- **FR-ITEM-02【P0】背包**：分类、排序、搜索、数量与容量上限（可选启用）；关键道具独立分区。
- **FR-ITEM-03【P0】装备栏**：栏位由游戏定义（武器/饰品/…），装备提供属性修正（表达式引用）。
- **FR-ITEM-04【P0】多层服装**：服装部位（上装/下装/内衣/外套/配饰…由游戏定义）× 层（内/中/外）；每件服装声明「覆盖部位与遮挡度」等开放数据字段（语义由游戏自用，引擎不解释）；着装状态可通过 `outfit.*` 在表达式中引用，并驱动动态描写（§5.2 宏 + §5.14 差分立绘）。
- **FR-ITEM-05【P0】换装 UI**：部位分层视图，一键便装/正装方案（游戏可配置预设）。
- **FR-ITEM-06【P1】物品时效与耐久**：可选的过期（时段）与耐久（次数）机制，字段开放。

### 5.8 身体与变身（FR-BODY）【P1】

**定位**：CoC/TiTS 验证过的核心特色。部位模板完全数据驱动（决策：引擎中立，不预设种族/形态语义），部位取值变化驱动描写与差分立绘。

数据形态示例：

```yaml
# data/body.yaml
parts:
  species: { values: [human, beast, demon], default: human }
  ears:    { values: [normal, pointed, furry], default: normal }
  tail:    { values: [none, fluffy, scaled], default: none }
pronouns: { rule: by_part, part: species, map: {human: [他,她], beast: [它]} }
# 描写片段（locales）：body.desc.has_tail_fluffy: "毛茸茸的尾巴在你身后晃动。"
# 场景宏：{if: "body.tail == 'fluffy'", then_text: "body.desc.has_tail_fluffy"}
```

- **FR-BODY-01【P1】部位模板**：游戏声明部位 → 取值集 → 默认值；玩家身体状态 = 部位→当前值映射，随存档持久化。
- **FR-BODY-02【P1】变身效果**：`set_body` 指令改变部位值（可临时/带时长回退）；变化事件可触发文本与媒体差分。
- **FR-BODY-03【P1】动态描写组合**：描写片段库按部位条件组合（叙事宏引用 `body.*`）；编辑器提供「按身体状态预览描写」。
- **FR-BODY-04【P1】代词与称谓**：可配置代词规则（按部位映射主语/宾语/所有格），作为插值变量供全部文本使用。
- **FR-BODY-05【P2】渐进变身**：部位值之间的过渡阶段与进度条（如「兽化 60%」），字段开放给游戏实现。

### 5.9 NPC 好感度与阵营声望（FR-NPCR）

**定位**：关系驱动内容解锁；声望把「个体关系」扩展到「群体态度」，为商店定价、事件条件提供变量。

- **FR-NPCR-01【P0】NPC 定义**：名称键、立绘引用（含差分表情，§5.14）、日程（§5.6）、初始好感、可交互入口。
- **FR-NPCR-02【P0】好感度**：数值区间（min/max）、变化效果 `favor`、阈值分段（关系阶段：陌生/熟识/挚友…游戏自定义），阶段变化触发效果与事件；`npc.<id>.favor`、`npc.<id>.stage` 进入表达式变量域。
- **FR-NPCR-03【P0】NPC 记忆**：每 NPC 独立 flag 命名空间 + 全局 flag；记录「见过某事件/说过某话」，供对话与事件条件引用。
- **FR-NPCR-04【P1】阵营声望**：阵营定义（城镇/帮派/教团…），`reputation` 效果与 `faction.<id>` 变量；声望阈值触发事件、影响商店定价（§5.11）与选项出现。
- **FR-NPCR-05【P1】关系面板**：展示已结识 NPC、关系阶段、（可选）好感进度条显隐策略由游戏配置（隐藏数值只显示阶段是常见做法）。

### 5.10 判定与战斗（FR-CMBT）

**定位**：两层能力——轻量的「判定」可嵌入任意叙事流；「回合制战斗」是独立的可中断交互模式（决策 D6）。

**A. CoC 式骰子检定**

- **FR-CMBT-01【P1】d100 技能检定**：`d100 <= 技能值` 判定成功；检定可绑定任意 `skill.*`/表达式值。
- **FR-CMBT-02【P1】检定等级**：普通 / 困难（÷2）/ 极难（÷5）；大成功（≤5 或 ≤技能/5，策略可配）、大失败（≥96 或 ≥100-（100-技能)/5 类变体，策略可配）；阈值策略在 manifest 级配置并支持游戏自定义规则预设。
- **FR-CMBT-03【P1】对抗检定**：双方各掷 d100 比相对成功度（成功等级高者胜，等级相同则技能值低者胜——CoC 规则，写入默认实现并允许配置）。
- **FR-CMBT-04【P1】奖励骰/惩罚骰**：十位数多骰取低（奖励）/取高（惩罚），支持链式多个。
- **FR-CMBT-05【P1】判定呈现与分支**：检定过程（骰值、目标、等级）有可视化动画/日志；结果直接路由到 `on_success / on_fail / on_critical / on_fumble` 目标（场景/段落/效果）。
- **FR-CMBT-06【P1】通用判定**：不绑定 TRPG 规则的「表达式值 + 随机 + 难度」判定，供非 CoC 游戏使用；两套判定并存。

**B. 回合制战斗**

数据形态示例：

```yaml
# data/enemies/street_thug.yaml
id: street_thug
name_key: enemy.thug
hp: { base: 30, formula: "30 + loop * 10" }     # 周目强化示例
attrs: { atk: 6, def: 2, spd: 4 }
skills: [thug_punch, thug_knife]
ai: { policy: weighted, weights: {thug_punch: 6, thug_knife: 2, guard: "when hp_pct < 0.3"}}
rewards: [ {money: {gold: "20 + rand(0,10)"}}, {item: {id: knife, chance: 0.3}} ]
```

- **FR-CMBT-07【P1】战斗定义**：敌人（HP/属性/技能表/AI 策略/奖励）、遭遇（敌方队伍、开场/回合/胜负文本键）、从事件或选项效果 `battle` 指令进入。
- **FR-CMBT-08【P1】回合流程**：速度决定行动序；玩家行动（攻击/技能/道具/防御/逃跑）→ 结算 → 敌方 AI 行动 → 回合结束钩子；战斗内状态效果（§5.5 的回合制时长）生效。
- **FR-CMBT-09【P1】AI 策略**：内置策略（加权随机 / 条件脚本 `when` 表达式），技能可声明条件与消耗。
- **FR-CMBT-10【P1】战斗 UI 与日志**：敌我状态栏、行动菜单、逐条战斗日志（可回看）、掷骰可视化。
- **FR-CMBT-11【P1】胜负结算**：胜利/失败/逃跑分别路由到效果序列与场景跳转；失败不强制等于游戏结束（由游戏决定「战败场景」）；奖励支持表达式与掉落几率。
- **FR-CMBT-12【P1】多敌人战斗**：敌方多人（目标选择）、我方队友参战为 P2（§5.24）。
- **FR-CMBT-13【P2】战斗模板库**：可复用遭遇模板 + 参数实例化。

### 5.11 经济与商店（FR-ECON）【P1】

- **FR-ECON-01【P1】多货币**：货币定义（金/银/代币…），钱包入 GameState，`money` 效果与 `wallet.<id>` 变量。
- **FR-ECON-02【P1】商店定义**：商品清单（物品、条件显示、库存与补货周期）、买价/卖价表达式（可引用声望、时段、周目、好感）、购买条件（如需要 flag）。
- **FR-ECON-03【P1】交易 UI**：浏览/购买/出售/回购（当次交易内回购同价）；价格随表达式动态计算并展示折扣理由文本键（可选）。
- **FR-ECON-04【P1】交易事件**：交易完成可触发效果（声望、flag、任务进度）。

### 5.12 成就与元进度（FR-ACHV）

**定位**：跨存档循环（决策 D7）。点数与已购增益存于 Profile，独立于存档槽位。

- **FR-ACHV-01【P1】成就定义**：解锁条件表达式（事件驱动优先 + 定期评估兜底）、点数、类型（普通/进度型 `progress_expr`/隐藏）、图标。
- **FR-ACHV-02【P1】解锁检测**：状态变更时增量评估相关条件（引擎维护条件→成就的依赖索引）；进度型成就显示进度条。
- **FR-ACHV-03【P1】解锁通知**：Toast（图标+名称键+点数），可批量合并；通知文本走 i18n。
- **FR-ACHV-04【P1】成就图鉴**：按分组展示，隐藏成就在未解锁前显示占位/提示语（游戏配置）；收集率统计。
- **FR-ACHV-05【P1】点数与 Profile**：点数累计入 Profile；读档回滚、删档不回收已获点数；Profile 含成就记录、点数余额、已购增益清单。
- **FR-ACHV-06【P1】开局增益（Perk）**：Perk 定义（消耗点数、效果：属性/初始物品/解锁选项与内容/额外对话）、依赖与互斥、可重复购买策略；新游戏流程内嵌 Perk 选择界面（见 §3.1）。
- **FR-ACHV-07【P1】退还与重置**：游戏可配置「重置点数」（回收全部已购 Perk 与点数余额，重新分配）；存档正在使用的 Perk 受保护策略由游戏选择（禁止重置/允许并标记）。
- **FR-ACHV-08【P1】Profile 导出导入**：与存档导出共享通道（§5.20），多设备迁移。

### 5.13 周目系统（FR-LOOP）

**定位**：同存档续章循环（决策 D8），与元进度双循环边界见 §3.4。

- **FR-LOOP-01【P1】周目计数**：GameState 内 `loop` 字段；`loop` 进入表达式变量域（如 `loop >= 2` 解锁事件/区域/对话变体）。
- **FR-LOOP-02【P1】结局定义与入口**：`endings.yaml` 定义结局（达成条件、结局文本键、图鉴信息、可标记「进入下一周目」或「终局」）。
- **FR-LOOP-03【P1】周目切换流程**：结局播放 → 周目转场界面（本周目统计摘要：用时/天数/事件数/成就）→ 执行继承/重置清单 → `loop+1` → 进入游戏配置的开局场景。
- **FR-LOOP-04【P1】继承/重置清单**：`loops.yaml` 按类别（属性/技能/物品/服装/身体/好感/声望/flag/任务/图鉴解锁/时间位置）配置继承或重置，支持白名单/黑名单与表达式例外（如「保留金币的 10%」）。
- **FR-LOOP-05【P1】周目专属内容**：事件/场景/选项/商店价格/敌人强度均可引用 `loop` 条件（示例见 §5.10 敌人 formula）。
- **FR-LOOP-06【P1】与迁移兼容**：周目状态纳入存档 schema 与迁移链（§5.19）；继承清单变更时可附迁移脚本。

### 5.14 媒体资源（FR-MEDIA）【P1】

**定位**：DoL/橙光验证的沉浸感基础。纯本地静态资源，无外部链接依赖。

- **FR-MEDIA-01【P1】媒体类型**：图片（背景/插图 CG/立绘/图标）——支持静态图（WebP/PNG/JPG）与**动图（GIF/动态 WebP/APNG）**，推荐动态 WebP（体积最优，目标浏览器全支持）；音频（BGM/音效）；视频为 P3 占位。
- **FR-MEDIA-02【P1】场景绑定**：场景/区域可绑定背景图与 BGM；BGM 切换支持淡入淡出与继续播放（同曲不重头）。
- **FR-MEDIA-03【P1】NPC 立绘与差分**：立绘 + 表情/状态差分（条件表达式驱动，如按好感阶段/身体部位/服装切换）。
- **FR-MEDIA-04【P1】文本内插图**：段落级插图（CG），自动收录 CG 图鉴（§5.16）。
- **FR-MEDIA-05【P1】音效触发**：选项点击、效果指令 `media` 播放一次性音效；文本打字音可选。
- **FR-MEDIA-06【P1】加载策略**：懒加载 + 关键资源预加载清单；加载失败的降级显示（占位/隐藏）与告警。
- **FR-MEDIA-07【P1】素材规范与版权**：格式（静态 WebP/PNG/JPG、动图 GIF/动态 WebP/APNG、OGG/MP3）；体积建议——静态图单张 ≤ 1MB、**动图单资产 ≤ 2MB、同屏并发动图 ≤ 2**（GIF 无帧间压缩，超额显著影响移动端流畅度）；manifest 内 credits 字段与许可声明模板。
- **FR-MEDIA-08【P1】全局媒体开关**：玩家可关闭 BGM/音效/图片（低带宽与无障碍场景）。
- **FR-MEDIA-09【P1】动图控制与降级**：动图资源可附带 `static` 静态帧字段；「减弱动画」设置（NFR-26）或低性能模式下以静态帧替代播放。GIF 无法程序化暂停/定位/同步，引擎不提供动图逐帧控制；需要与文本、音频精确同步的演出（如差分表情切换节奏）建议由叙事节奏切图实现，序列帧（sprite sheet）播放列入 OQ-12 评估。

### 5.15 阅读体验 QoL（FR-READ）【P1】

**定位**：Ren'Py 验证的阅读型游戏基础体验，长文本游戏的口碑项。

- **FR-READ-01【P1】已读跳过**：以场景键粒度记录已读；「跳过已读」快进模式（再次点击/按键中断）。
- **FR-READ-02【P1】自动播放**：按段落长度计时自动推进（速度分级可调），遇到选项/判定/战斗自动暂停。
- **FR-READ-03【P1】回滚**：每次玩家选择前打 checkpoint 快照；支持回退到上一次选择（栈深度可配置，默认 5）；回滚同时恢复状态与文本位置；与成就/Profile 解耦（回滚不影响已解锁成就）。
- **FR-READ-04【P1】历史回看**：完整文本日志（虚拟滚动），按时间/场景分组，可回看判定与战斗日志。
- **FR-READ-05【P1】排版设置**：文字速度、字号、行距、主题（联动 §5.24 UI 主题）；设置即时生效并持久化。
- **FR-READ-06【P1】快捷键**：导航/确认/跳过/自动/存档等键盘映射 + 自定义说明页；移动端手势（左右滑 = 回退/前进提示）。

### 5.16 回想图鉴与结局收集（FR-GAL）【P1】

- **FR-GAL-01【P1】场景回想**：标记为 gallery 的场景解锁后可在图鉴中以「只读模式」重放（不影响当前 GameState；回想版本使用解锁时的参数快照渲染文本）。
- **FR-GAL-02【P1】结局图鉴**：结局收集页（达成过的结局、隐藏结局占位与提示文本键、达成条件提示可配置延时显示）；结局解锁入 Profile（跨周目/跨存档收集）。
- **FR-GAL-03【P1】CG 图鉴**：已见插图浏览（缩略图/大图），未解锁打码或占位策略可配。
- **FR-GAL-04【P1】事件收集率**：按区域/类别统计事件触发情况（对玩家显示收集率百分比，隐藏类目策略可配）。

### 5.17 统计页面（FR-STAP）【P1】

**定位**：ChoiceScript 式作者自定义统计视图，兼具角色卡总览。

- **FR-STAP-01【P1】自定义布局**：`stats-page.yaml` 定义分组/条目（取值表达式或文本键）、显示条件、图表样式（条形/雷达/文字）；编辑器提供设计器预览。
- **FR-STAP-02【P1】角色卡**：内置总览模板：属性/技能/身体状态/着装/关系/任务概要，各分区可开关。
- **FR-STAP-03【P1】游玩统计**：总用时、游戏内天数、事件计数、判定次数与成功率、战斗胜负、周目数（作为进度型成就数据源）。

### 5.18 调试与作弊面板（FR-DEBG）【P1】

**定位**：DoL 的 debug 模式验证的刚需。作者调试效率 + 玩家可选的便利性。

- **FR-DEBG-01【P1】模式开关**：游戏 manifest 声明是否向玩家开放作弊面板；编辑器预览模式恒定可用完整调试。
- **FR-DEBG-02【P1】变量监视器**：查看/检索/修改 GameState 任意路径（含 NPC 好感、flag、时间、物品、任务）；修改产生日志。
- **FR-DEBG-03【P1】跳转与快进**：跳转任意场景/地点/事件、时间快进（时段/天/周）、直接触发战斗/结局/周目切换。
- **FR-DEBG-04【P1】表达式控制台**：即时求值任意表达式（只读），显示解析的 AST。
- **FR-DEBG-05【P1】事件触发日志**：时段推进时事件池评估的过程记录（评估了哪些事件、为何未触发）。
- **FR-DEBG-06【P1】作弊指令集**：无敌/加钱/全物品等常用开关（走统一效果指令，游戏可扩展）。
- **FR-DEBG-07【P1】错误边界**：单场景/单指令错误不崩溃全局，显示错误卡片（键、原因、上下文）并允许继续/回退。

### 5.19 版本与存档迁移（FR-MIGR）

**定位**：决策 D9——三层版本 + 迁移链 + 引用容错。架构字段 M0 预留，完整机制 M2.5 落地（§7）。

- **FR-MIGR-01【P0】三层版本记录**：manifest 记录 `gameVersion / schemaVersion / minEngineVersion`；每个存档与 Profile 记录三者 + 引擎实际版本。
- **FR-MIGR-02【P0】兼容判定**：加载时比较版本——`schemaVersion` 相同直接载入；低于则进入迁移流程；高于当前引擎能力则明确报「存档来自更新版本」并拒绝（不损坏数据）。
- **FR-MIGR-03【P1】迁移脚本链**：`data/migrations/` 内每级 schema 一个脚本（受限 API：纯数据变换，禁止网络/存储访问）；引擎按 vN→vN+1 逐级执行并记录迁移日志。
- **FR-MIGR-04【P1】迁移安全**：迁移前自动备份原档（标记为 pre-migration）；任一步失败即中止并回滚到备份，向用户展示可诊断错误（失败步骤、原因），并提供导出备份入口。
- **FR-MIGR-05【P1】引用容错**：游戏包可声明 `redirects`（旧 ID → 新 ID 映射）；存档中引用已不存在的场景/物品/NPC/任务时按映射转换，未映射则回退到游戏声明的安全场景并 Toast 告警，绝不白屏。
- **FR-MIGR-06【P1】Profile 迁移**：成就/点数/已购增益使用同机制；Profile 迁移独立于存档迁移执行。
- **FR-MIGR-07【P1】发布向导联动**：编辑器发布时对比上一发布版本，检测 schema 变化即生成迁移脚手架与 ID 变更清单（§5.23）。

### 5.20 存档系统（FR-SAVE）

- **FR-SAVE-01【P0】多槽位**：槽位数量游戏可配（默认 10）；元信息含：周目数、位置、时间、游玩时长、任务/成就摘要、缩略文本快照。
- **FR-SAVE-02【P0】自动存档**：可配置触发点（时段推进/场景进入/事件完成），独立自动槽位轮换（默认保留 3 份）。
- **FR-SAVE-03【P0】快速存读**：单键快存/快读（独立槽位），键盘与 UI 均可触发。
- **FR-SAVE-04【P0】导出/导入**：存档导出为 JSON 文件（含 Profile 可选勾选）；导入时校验结构与版本并走迁移流程。
- **FR-SAVE-05【P0】写入安全**：IndexedDB 事务写入 + 写前备份旧档（原子性）；存储 quota 不足时显式报错。
- **FR-SAVE-06【P1】槽位管理**：重命名/删除/复制（二次确认）；存档内含引擎与游戏版本（迁移依据）。
- **FR-SAVE-07【P2】存档校验和**：防手改损坏的轻量校验（非安全对抗，仅数据完整性）。

### 5.21 内容分级与过滤（FR-CGRD）

**定位**：决策 D13。引擎中立：只提供标签机制与过滤执行，标签语义与游戏整体分级声明由作者定义并自负内容责任（§8 合规）。

- **FR-CGRD-01【P1】标签体系**：游戏在 `content-tags.yaml` 自定义标签（如 暴力/恐怖/惊悚…），manifest 声明整体分级描述与警告文本键。
- **FR-CGRD-02【P1】内容标注**：场景/事件/选项/文本段/物品描述可打标签。
- **FR-CGRD-03【P1】过滤执行**：玩家在设置面板开关各标签后——被屏蔽事件不再进入事件池；被屏蔽场景/段落替换为占位文本键（游戏提供）或跳过；被屏蔽选项隐藏。过滤变更即时生效。
- **FR-CGRD-04【P1】首次启动向导**：新玩家首次进入游戏时展示内容警告页与标签开关（可跳过、可在设置中修改）。
- **FR-CGRD-05【P1】任务降级策略**：被屏蔽内容关联的任务线由游戏配置处理方式（可完成性不得被破坏——编辑器校验提示）。

### 5.22 玩家界面总纲（FR-UI）

- **FR-UI-01【P0】主布局**：主文本区（阅读流）+ 侧栏（状态/时间/导航）+ 底部选项区；桌面双栏、移动端侧栏折叠为标签页（Tab 切换状态/地图/任务）。
- **FR-UI-02【P0】世界地图/导航面板**：区域图 + 地点列表（含解锁状态与移动消耗）；当前位置高亮（§5.3）。
- **FR-UI-03【P0】状态面板**：属性/技能/状态效果/钱包/着装概要；数值变化高亮（§5.5）。
- **FR-UI-04【P1】功能面板**：任务日志（§5.4）、成就图鉴（§5.12）、统计页（§5.17）、回想/结局/CG 图鉴（§5.16）、关系面板（§5.9）、百科（§5.24）。
- **FR-UI-05【P0】设置面板**：语言、文本速度/字号、BGM/音效/图片开关、内容标签（§5.21）、快捷键说明、关于/版本信息（三版本号展示）。
- **FR-UI-06【P0】主菜单**：继续（最近存档）/ 新游戏（含 Perk 选择流程）/ 读档 / 成就 / 设置 / 关于。
- **FR-UI-07【P1】通知系统**：统一 Toast（成就/物品/属性/系统），防刷屏合并策略。
- **FR-UI-08【P1】版本不兼容提示**：存档/游戏包版本不匹配的专门界面（§5.19 场景），提供原因与可选操作（导出备份）。
- **FR-UI-09【P1】移动端适配**：≥360px 视口的可用布局；触控目标、滚动性能、软键盘下的输入体验（角色命名等）。

### 5.23 可视化编辑器（FR-EDTR）

**定位**：作者生产力核心（M3，决策 D1）。以下均为 P1（另标注者除外）。

**A. 项目与素材**

- **FR-EDTR-01【P1】项目管理**：新建（模板/空白）/打开/最近列表；项目自动快照备份（可回滚到编辑动作前的副本）；游戏包目录可视化浏览。
- **FR-EDTR-02【P1】素材库**：图片/音频导入、预览、重命名（保持引用同步）、引用计数、未使用素材清单。

**B. 场景画布**

- **FR-EDTR-03【P1】节点画布**：React Flow 场景图；节点 = 场景，边 = 跳转（含条件摘要标签）；按区域分组泳道显示；缩放/小地图/搜索定位。
- **FR-EDTR-04【P1】大纲树**：区域→地点→场景的树形大纲，双击定位画布节点；拖拽调整归属。
- **FR-EDTR-05【P1】画布性能**：大项目（2000+ 场景）虚拟化渲染与按区域折叠。

**C. 内容编辑**

- **FR-EDTR-06【P1】场景编辑器**：TipTap 富文本（白名单标签）+ 叙事宏插入向导（条件文本/首次再次/随机段）；选项表格化编辑（条件/效果/跳转下拉引用选择）；编辑产生的文本自动落到 `locales/` 当前工作语言并登记键。
- **FR-EDTR-07【P1】数据库编辑器**：属性/技能/状态/NPC/阵营/物品/服装/身体部位/商店/事件/任务/成就/Perk/结局/周目规则/标签的表格式管理 + 表单校验（Zod 即时报错、引用下拉防悬空）。
- **FR-EDTR-08【P1】表达式编辑器**：语法高亮、变量域自动补全（attr/npc/…感知当前上下文）、错误即时标注、选中试算（当前预览状态求值）。
- **FR-EDTR-09【P1】效果构建器**：效果指令可视化编排（添加/排序/条件包裹），同时可切源码视图。

**D. 预览与调试**

- **FR-EDTR-10【P1】一键试玩**：内嵌 runtime 预览窗口；数据变更热更新（保持当前 GameState 尽量兼容）。
- **FR-EDTR-11【P1】预览调试工具**：变量监视、跳转任意场景、时间快进、周目模拟（直接进入 loop=N 状态）、触发任意事件/战斗/结局、作弊面板（§5.18 完整版）。
- **FR-EDTR-12【P1】多语言预览**：任意语言/回退状态切换预览；缺失键高亮。

**E. 文本与翻译管理**

- **FR-EDTR-13【P1】字符串总表**：键/主语言/工作语言三栏对照，状态标记（缺失/过期/占位符不一致）；按命名空间过滤。
- **FR-EDTR-14【P1】翻译包导出导入**：CSV/XLIFF 往返，导入时合并策略（覆盖/跳过/冲突提示）。

**F. 校验与发布**

- **FR-EDTR-15【P1】校验中心**：引用完整性（悬空跳转/文本键/物品/NPC 引用/媒体路径）、ID 重复、表达式错误、翻译缺失、内容标签缺失（有 tags 机制却未标注的高危项提示）、被过滤内容破坏任务可完成性提示（§5.21）。
- **FR-EDTR-16【P1】ID 稳定性检查**：重命名/删除已被引用或可能被存档引用的对象时警告并要求确认；提供 ID 变更登记（生成 redirects 建议，§5.19）。
- **FR-EDTR-17【P1】发布向导**：版本号与变更记录填写 → 与上一发布版 diff（schema 变化提示 → 迁移脚手架生成，§5.19）→ 校验门禁 → 导出（§5.25）。
- **FR-EDTR-18【P2】团队协作辅助**：项目导出为纯文件目录天然支持 Git；编辑器提供「文本键变更对比报告」辅助译员同步（不含在线协作）。
- **FR-EDTR-19【P1】编辑器自身 i18n**：中/英界面切换；编辑器数据与项目数据隔离存储。

### 5.24 P2 功能包（FR-XTRA）

- **FR-XTRA-01【P2】物品合成**：配方（材料/产物/条件/解锁方式）与制作 UI；合成可关联任务与成就。
- **FR-XTRA-02【P2】同伴/队伍**：同伴定义（成长/好感/日程/参战技能）、战斗中入队（复用 §5.10 敌我框架的己方多单位）、非战斗跟随互动。
- **FR-XTRA-03【P2】程序化内容生成**：事件/NPC 模板 + 占位符实例化（池 + 种子随机，可复现）；模板参数走数据不写脚本。
- **FR-XTRA-04【P2】Mod 支持（数据覆盖包）**：overlay 包结构（只含差异 data/locales/assets + mod manifest）；声明兼容的游戏版本范围；加载顺序与冲突检测报告；**安全边界：Mod 只能是数据，不执行任意脚本**（§6.5）。
- **FR-XTRA-05【P2】游戏级 UI 主题**：主题包（色板/字体/布局密度/背景纹理，CSS 变量契约）；玩家可在游戏提供的主题间切换；编辑器主题设计器可视化编辑并随包导出。
- **FR-XTRA-06【P2】百科 Codex**：词条定义与解锁条件（事件/物品/NPC 遇见触发），图鉴式浏览，词条文本走 i18n。

### 5.25 导出与分发（FR-EXPT）

- **FR-EXPT-01【P1】静态包导出**：产出 `index.html + engine runtime + 编译后 JSON 数据 + locales + assets + manifest`；数据经压缩与校验；可直接托管 GitHub Pages / 任意静态服务器 / 本地 file 打开（file 模式的限制在文档标注）。
- **FR-EXPT-02【P1】单文件导出**：全部资源内联为单一 HTML（便于 itch.io / 网盘分发）；超过浏览器限制时提示并建议分包。
- **FR-EXPT-03【P1】Electron 打包**：exporter 将静态包封装为桌面应用（Win/macOS/Linux）；更新方式为整包替换（无自动更新，理由与替代方案在发布说明中给出）。
- **FR-EXPT-04【P1】发布清单**：包内含版本、changelog、credits、内容分级声明（§5.21）；导出产物附带完整性清单（文件哈希）。
- **FR-EXPT-05【P1】PWA 支持（可选）**：静态包可附带 manifest 与 service worker 模板（游戏可选启用离线游玩；模板由引擎提供）。

### 5.26 作者脚本扩展（FR-SCR）【P1】

**定位**：双轨创作中的「代码轨」（决策 D15）。面向具备开发能力的作者：以 TypeScript 编写自定义逻辑，**导出时编译**进静态包，运行时只执行编译产物、从不解释源码。与数据 DSL 的关系：DSL（§4.5、FR-NARR）仍是默认创作方式，也是校验、回滚与存档迁移的基准；脚本轨是对它的**受控超集**。注册 API 纳入 M3 之前的引擎公开 API 冻结范围（R-07）。

- **FR-SCR-01【P1】注册式扩展点**：作者脚本经引擎类型化注册 API 扩展四类能力——自定义效果指令、自定义条件/表达式函数、自定义检定规则（如非 CoC 规则集）、系统钩子（时段推进 / 周目切换 / 战斗回合等生命周期的前置后置处理）。
- **FR-SCR-02【P1】能力受限的脚本 API**：脚本不得直接改写 GameState 原始对象，一切状态变更必须经引擎事务 API（以效果指令包装）执行——以此保障回滚快照（FR-READ-03）、调试日志（FR-DEBG）与存档迁移（FR-MIGR）的一致性；绕过事务 API 的状态访问在开发期即报错。
- **FR-SCR-03【P1】编译与打包**：导出器将 `scripts/` 下 TypeScript 编译为静态包内普通 JS 模块并执行类型检查，类型错误即发布门禁失败；编辑器内预览走同一编译路径（增量编译），保证「预览 = 导出」。
- **FR-SCR-04【P1】脚本与数据的契约校验**：游戏数据引用的自定义指令/函数在加载期核对注册表，缺失按悬空引用同级处理并进入校验中心（FR-EDTR-15）。
- **FR-SCR-05【P1】存档责任**：脚本注册的指令须声明是否修改存档字段（`touchState`）；新增存档字段必须同步登记进 schema 与迁移链（FR-MIGR），发布向导对未登记的 `touchState` 给出阻断级提示。
- **FR-SCR-06【P0】安全边界（不变式）**：只有游戏作者经导出流程产出的静态包可包含脚本；**Mod（FR-XTRA-04）与导入存档（FR-SAVE-04）永远不得携带脚本**；引擎运行时不提供任何运行期脚本解释或动态加载能力（NFR-19/NFR-20）。
- **FR-SCR-07【P2】官方脚本片段库**：提供常用片段示例（节日日历、随机遭遇增强、自定义检定规则等），可复制进项目作为起点。

## 6. 非功能性需求

编号 `NFR-<序号>`，与功能性需求同优先级体系。

### 6.1 性能

- **NFR-01【P0】** 场景切换（文本渲染 + 媒体就绪）≤ 100ms（中端桌面 / 近三年移动设备）。
- **NFR-02【P0】** 时段推进的事件池评估（含全部条件求值）≤ 16ms；通过条件依赖索引与脏标记增量评估实现（风险 R-02）。
- **NFR-03【P0】** 存档写入 ≤ 500ms（存档体 ≤ 10MB）；读写不阻塞 UI 主线程（Worker 化评估）。
- **NFR-04【P0】** 首次可交互 ≤ 3s（标准静态托管、引擎+运行时资源 gzip ≤ 600KB 目标，不含游戏媒体）。
- **NFR-05【P1】** 历史日志/长文本列表虚拟滚动，10k 条目无卡顿。
- **NFR-06【P1】** 编辑器画布在 2000 节点 + 折叠分组下保持可交互帧率。

### 6.2 兼容性

- **NFR-07【P0】** 桌面：Chrome / Edge / Firefox / Safari 最近两个大版本。
- **NFR-08【P0】** 移动：iOS Safari 15+、Android Chrome 10+，≥360px 视口可用。
- **NFR-09【P1】** Electron：Windows / macOS / Linux 三平台打包（依赖社区基础设施）。
- **NFR-10【P1】** IndexedDB 不可用（隐私模式等）时降级到内存 + 频繁导出提醒，不静默丢档。

### 6.3 可扩展性与可维护性

- **NFR-11【P1】** 引擎系统模块化：效果指令、条件函数、检定规则、判定动画可由游戏包注册扩展，两条途径——数据注册（受限插件数据）与作者脚本注册（FR-SCR，导出期编译）；运行时均无脚本解释。
- **NFR-12【P0】** 单一 schema 来源：Zod 定义生成 TS 类型，engine / editor / exporter 共用；schema 变更必须伴随版本与迁移方案（§5.19）。
- **NFR-13【P0】** engine 包公共 API 文档化 + 语义化版本；`engine` 核心逻辑单测覆盖率 ≥ 80%，发布前跑全量旧档回归（§7 发布门禁）。
- **NFR-14【P1】** E2E 冒烟用例（新游戏→游玩→存→读→继续）纳入 CI。

### 6.4 数据与版本

- **NFR-15【P0】** schema 演进原则：只增字段不改语义；废弃字段保留一个版本周期并在校验器中警告；表达式语法独立版本化。
- **NFR-16【P0】** 存档/Profile 前向兼容策略见 FR-MIGR-02：可升级、可拒绝（高于引擎能力）、绝不静默损坏。
- **NFR-17【P1】** 游戏包完整性：导出附带文件哈希清单（防传输损坏 + Mod 冲突检测基础）。

### 6.5 安全

- **NFR-18【P0】** 富文本渲染白名单 + sanitizer，任何来源（含译文、Mod）的标记都不可注入脚本。
- **NFR-19【P0】** 表达式仅 AST 解释执行，禁止 `eval` / `new Function`；函数白名单无 I/O 能力。作者脚本为导出期编译产物（FR-SCR-03），引擎在运行期不加载、不解释任何脚本源码——该禁令对 Mod 与导入存档无条件生效（FR-SCR-06）。
- **NFR-20【P2】** Mod 为纯数据覆盖（FR-XTRA-04），不执行脚本；加载时做冲突与完整性检测。
- **NFR-21【P1】** 静态包提供 CSP 模板；媒体仅允许包内资源；存档导入先校验结构与版本。

### 6.6 可靠性

- **NFR-22【P0】** 存档原子写入与写前备份（FR-SAVE-05）；迁移自动备份（FR-MIGR-04）。
- **NFR-23【P1】** 运行时错误边界：单场景/指令错误不崩溃全局（FR-DEBG-07）；未捕获错误提供导出诊断包（脱敏）。
- **NFR-24【P1】** 编辑器自动快照 + 崩溃恢复（回到上次编辑动作）；项目数据与编辑器程序数据隔离。

### 6.7 无障碍

- **NFR-25【P1】** 全键盘操作（含选项编号快捷选择）；焦点管理符合 WAI-ARIA。
- **NFR-26【P1】** 字号/行距/对比度可调；打字机效果可关闭；动画（骰子/转场/动图）可减弱——动图经静态帧降级实现（FR-MEDIA-09）。
- **NFR-27【P3】** TTS 朗读展望：文本流结构化已满足前提，朗读控制为远期。

### 6.8 国际化工程

- **NFR-28【P0】** 文本键机制覆盖全部玩家可见文本（§5.1）；UI 布局对译文长度膨胀（中→英 +40%）弹性适配。
- **NFR-29【P1】** 数字/日期/序数本地化格式化；RTL 语言架构预留（字符串方向包裹约定），不做首发承诺。

## 7. 里程碑规划

周期为单人兼职开发的建议估计，按「每期结束都有独立价值」排布。**发布门禁（每个里程碑）**：全量单测 + E2E 冒烟 + 旧档读取回归用例通过。

| 里程碑 | 主题 | 范围（对应 FR） | 验收标准 |
|---|---|---|---|
| **M0**（2–3 周） | 技术验证 | monorepo/CI；YAML 加载+校验；场景/选项/表达式/效果指令；文本键渲染；最小 runtime-ui；存档版本字段预留（FR-MIGR-01） | 手写数据的 3 场景分支 demo 浏览器可玩；表达式错误能静态报出 |
| **M1**（4–6 周） | 运行时 MVP（P0 全量） | 探索/事件/任务；数值/时间/物品服装/NPC；存档多槽位+导出导入；玩家 UI（主布局/地图/任务/设置/主菜单）；媒体渲染（图/BGM 基础）；多语言切换+回退 | 官方 demo：3 区域、10+ 事件、2 条任务线，桌面+移动可玩；zh/en 切换；存档导出导入往返一致 |
| **M2**（4–6 周） | 系统深化 | CoC 检定+通用判定；回合制战斗；成就+点数+Perk；周目系统；阅读 QoL（跳读/自动/回滚/历史）；调试面板；经济商店；身体变身；阵营声望 | demo 含战斗遭遇与骰子呈现；10+ 成就、3+ Perk；「同存档进入第二周目且继承清单生效」用例通过；回滚 5 步状态一致 |
| **M2.5**（2 周） | 迁移机制 | FR-MIGR-03～07 全量；版本不匹配 UI | M1 时期旧档在当前 demo 读取成功（回归用例入库）；人为构造失败迁移，验证备份还原 |
| **M3**（6–8 周） | 可视化编辑器 | FR-EDTR-01～14 + 校验中心（15–16）；发布向导可延至 M4 | 完全用编辑器复刻 M1 demo（零手写 JSON）；画布 500 节点流畅；校验中心抓出人工埋入的 5 类错误 |
| **M4**（3–4 周） | 打磨与分发 | 静态包/单文件导出；Electron；内容分级全流程；回想/结局/CG 图鉴；统计页；PWA 可选；FR-EDTR-17 发布向导；作者脚本编译打包（FR-SCR-03，注册 API 已随 M2 末冻结） | 导出包在 GitHub Pages 与 Electron 均可玩；单文件导出达标；「屏蔽某标签后关联任务仍可完成」用例通过；含一个自定义脚本指令的 demo 用例编译导出成功 |
| **M5**（持续） | P2 功能包 | 合成 / 同伴 / 程序化生成 / Mod / UI 主题 / 百科（FR-XTRA） | 每项功能附带独立验收用例与文档后再发布 |

裁剪原则：M5 各项相互独立可整体延后；M2 内部可按「判定→战斗→成就周目→QoL」再拆分交付。

### 8.1 风险与缓解措施

|---|---|---|---|

## 附录 A. 术语表

| 术语 | 定义 |
|---|---|
| 游戏包（Game Package） | 编辑器产出、引擎可运行的完整游戏数据：`data/ + locales/ + assets/ + manifest` |
| manifest | 游戏包清单：名称、入口、语言、内容标签声明、三层版本号等 |
| 文本键（Text Key） | 面向玩家文本的全局唯一标识，指向 `locales/<lang>/` 中的译文 |
| Profile | 跨存档持久数据：成就记录、成就点数、已购开局增益、结局收集 |
| 周目（Loop） | 同一存档内的游戏轮次；`loop` 计数可作为内容条件 |
| Perk（开局增益） | 新游戏时用成就点数兑换的开局优势 |
| 事件池（Event Pool） | 绑定「地点 × 时段 × 条件」的事件集合，按时段推进与进入地点时评估 |
| 时段（Slot） | 游戏自定义的一天划分单位（早/午/晚/夜等），时间推进的基本刻度 |
| 叙事宏（Macro） | 段落内的条件文本、首/再次区分、随机选段等动态文本结构 |
| 迁移链（Migration Chain） | 旧存档 schema 逐级升级到当前版本的脚本序列 |
| redirects | 旧 ID → 新 ID 的引用映射，用于内容重构后的存档容错 |
| 数据覆盖包（Overlay Mod） | 只含差异数据、按声明叠加的 Mod 形态（P2） |
| 静态包（Static Build） | 导出的纯静态站点文件，可托管于任意静态服务器 |
| 受限插件数据 | 游戏包内以数据形式注册的效果指令/条件函数/规则扩展（非脚本执行） |
| 作者脚本（Author Script） | 游戏作者以 TypeScript 编写、**导出时编译**进静态包的扩展逻辑（FR-SCR）；Mod 与导入存档不得包含 |
| Zod schema | 数据结构的单一权威定义，同时生成运行时校验与 TS 类型 |
